# 设计取舍与常见问题

## 为什么用 VMware 虚拟机？

本项目要观察 SELinux 端口拒绝、systemd 单元、boot 与 invocation 等系统级事件。虚拟机让这些机制按原生 Linux 环境运行。容器可用于网络或应用层对照，但不直接替代 L02 的 SELinux 端口实验。

## 如何验收故障注入与恢复？

用同一轮 run_id 关联注入、检查、恢复与清理；L02 结合 AVC、SYSCALL、SOCKADDR、PID、unit 与时间窗，M01 对照执行计划与结果指纹，M04 核对恢复数据和应用读取结果。SHA-256 用于关联文件版本，而不是证明日志不可伪造。

## 为什么用 INVISIBLE，而不是 DROP INDEX？

MySQL 8.4 InnoDB 支持原子 DDL。INVISIBLE 无需重建索引，适合反复模拟读查询失去目标索引的情况；但索引物理上仍存在，不能模拟删除后写入或空间变化。

## 502 和 504 如何区分？

502 是网关连接上游失败或收到无效响应；504 是等待上游超时。应结合上游进程、Nginx 日志、请求耗时定位。proxy_read_timeout 限制的是相邻读操作之间的等待时间，不是整个请求的总时长。

## 如何看待性能数字？

M01 两组在同一实验机和数据集上，预热 10 次、测量 50 次，并检查执行计划与查询结果。30.55 ms 和 0.84 ms 是对应实验的平均值，不等于其他业务场景的承诺。

## 当前版本的验证缺口有哪些？

v41 整包空盘安装、云端 CI 与真实跨重启恢复仍待验证。优先补齐可复现部署，再扩展 Kubernetes 对照实验。
