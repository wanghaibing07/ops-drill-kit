# Ops Fault Recovery | Linux 服务故障诊断与恢复验证

**个人项目 · Linux 运维 / 技术支持 / 实施交付方向**

基于 VMware Workstation、Rocky Linux 9.8、Nginx、FastAPI 和 MySQL 搭建订单服务，围绕 **SELinux 端口拒绝、Nginx 502/504、MySQL 查询退化与误删恢复**，实现故障定位、恢复处置、业务验收及证据留存。

**可核验成果：** 已完成 L02、N03、M01、M04 四类场景的诊断与恢复闭环；在 **50 万条合成订单**的固定查询中，联合索引使平均耗时由 **30.55 ms 降至 0.84 ms**；使用 MySQL 全备与 binlog 恢复误删前状态，并由隔离订单 API 验证业务可读。项目规划 13 类场景，其余完成情况见下文。

**快速查看：** [代表性案例与证据](案例与证据.md) · [工程设计问答](docs/design-faq.md) · [证据索引](docs/appendix/evidence-index.md) · [场景状态](#场景覆盖与完成状态)

## 工程目标

- **故障可控**：限定操作对象、运行身份与变更范围。
- **恢复可执行**：统一 CLI 管理注入、检查、恢复和复位，结合超时清理。
- **结果可验收**：结合系统审计、运行状态、业务响应和查询执行计划，建立可复核的判定条件。
- **过程可追溯**：保留 `run_id`、证据摘要和失败记录，不以重试结果覆盖失败事实。

## 系统架构

```text
VMware Workstation
└── Rocky Linux 9.8（隔离验证环境）
    ├── Nginx :8080 ─────── 反向代理
    ├── orderguard-api :8000 ── FastAPI 订单接口
    ├── MySQL 8.4 LTS ───── 本地回环，业务库与影子库
    ├── /var/lib/opsdrill/events.jsonl ── 受保护事件记录
    └── /var/backups/opsdrill/ ────────── 故障验证证据
```

业务链路为 **Nginx → FastAPI → MySQL**。基础业务库使用 5 条合成订单；影子库使用 50 万条合成订单，用于查询性能和数据恢复验证。

## 核心实现

### 统一控制接口与生命周期

在已安装的实验机项目目录中，通过 `bin/opsdrill` 管理 `start → check → resolve → reset`。每次任务创建独立 `run_id`，后续操作使用 `--expect-run-id` 校验运行身份，防止误清理其他任务资源。适用场景配置 120 秒或 180 秒 watchdog，验证超时清理与异常中断处理。

### 多维证据关联与验收机制

以 L02 为例，将 `AVC`、`SYSCALL`、`SOCKADDR`、`PID` 与 boot、unit、日志时间窗交叉关联，判断 SELinux 是否确实拒绝本次 Nginx 端口绑定。证据不足时维持 `PENDING`，不将历史日志计入本轮结果。

结果文件使用 SHA-256 进行版本对应核验；摘要用于避免引用错误的证据版本，不单独证明日志真实性。

### 变更约束与恢复可靠性

- **L02**：保持 SELinux Enforcing，选择策略允许的端口恢复服务，不额外创建持久 SELinux 例外。
- **N03**：将首次 504 注入返回 404 的失败归档；定位缺失的 systemd drop-in，并补充安装器文件创建与校验。
- **M01**：采用 `INVISIBLE` 控制联合索引可见性，避免通过反复物理删除索引构造查询退化；不修改全局慢查询等参数。
- **M04**：对事务边界采用审计约束，审计失败时停止回放，通过独立账本受控续接；复位时结合实例、进程、cgroup、socket 复核状态。

| [N03 · 网关 502 / 504](docs/cases/02-N03-网关502与504.md) | 上游连接失败与响应超时 | 两种变体均完成验证；首次 504 返回 404，失败记录保留并修复对应安装缺陷 |
| [M01 · MySQL 索引](docs/cases/03-M01-索引失效.md) | 联合索引与访问路径 | 50 万条合成订单固定查询对照，平均延迟 **30.55 ms → 0.84 ms**；历史索引创建与当前可见性控制分别记录 |
| [M04 · 时间点恢复](docs/cases/04-M04-误删与时间点恢复.md) | MySQL 误删恢复与应用可用性 | 全备应用读取金额 100/200，PITR 后读取 101/200，隔离 API 两阶段均返回 HTTP 200；另完成 50 万行恢复副本的应用联读验证 |
